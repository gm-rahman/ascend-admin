GOTCHAS LEARNED THIS SESSION (don't rediscover these)
====================================================================
1. Literal unicode escapes in source: some files contain the LITERAL
   6-character text — (backslash-u-2-0-1-4) inside string
   literals, not an actual em-dash glyph. The Edit tool's string
   matching will silently fail if you paste a real "—" character
   instead of the literal escape text, or vice versa — always grep/Read
   the exact bytes first (or check with `cat -A` in Bash) before
   writing an old_string that spans such a line. When Edit keeps
   failing for no visible reason, fall back to a small Python script
   that reads/writes the file with explicit UTF-8 encoding and does
   line-range replacement by index (this is what worked for scs.tsx's
   workout array — see conversation history for the exact script).

2. Invalid Tailwind v4 shades produce ZERO CSS silently (not a fallback
   color — literally no rule generated), which can make text invisible
   or uncolored depending on inherited color. Valid shade scale is
   exactly {50,100,200,300,400,500,600,700,800,900,950}. Grep pattern:
     grep -nE "(text|bg|border)-[a-z]+-[0-9]{3}\b" <file>
   Two instances already fixed in scs.tsx (see above). Worth a repo-wide
   sweep before final verification (Phase 6 / Final step is the natural
   place for this).

3. Don't re-enter plan mode / call ExitPlanMode again — the plan is
   already approved and implementation is already underway. The user

4. This is a mock/prototype app, no backend. All "records" are local

   dialog is just "pass the already-in-scope row object's fields into
   RecordDetailDialog" — no data fetching needed.
